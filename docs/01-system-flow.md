# chrono-zoetrope 시스템 플로우 — 기능·입출력 중심

> 짝 문서: [02-prompts.md](02-prompts.md) (프롬프트 원문 전체)
>
> 실행 주체 요약
> - **cdb-crafter** — 참가자 입력 수집 웹앱 (Firestore/Storage에 저장)

> - **server/index.mjs** — 전시 런타임 (상태 기계, 유령 대화, TTS 중계, 돔 안무)

## 0. 입력 수집 (cdb-crafter)

**기능** — 참가자가 인생그래프를 그리며 삶의 기록을 제출한다. 이후 모든 생성의 유일한 원천 데이터.

**INPUT (참가자가 직접 입력)**
- 이름, 생년월일 → `pid = 이름_생년월일6자리` (Firestore 문서 키가 pid의 정본)
- 15구간(0~3세 … 85~90세) 점 배열: 구간당 최대 3개 점 `{ age(정확한 나이), x(감정 위치 0~1), event(사건), companion(함께한 사람), place(장소), imageURL(사진, 과거~현재만) }`
- selections: influential / best / worst 순간 선택 + 이유
- myLife: 인생 모토, 버킷리스트 (체험 후 재작성분은 배열로 누적 — first/latest 구분)
- funeral: 상주(chiefMourner), 묘비명(epitaph), 장례 방식(funeralMethod), 안식처(burialSite), 마지막 편지(messages: 수신인+본문)

**OUTPUT** — Firestore `profiles/{pid}` 문서(first/second/third 세션 필드) + Storage 사진 업로드. status `submitted`.

# A. Chamber 사전 생성 (profile-worker — 체험 전 백그라운드)

순서: A1 성별 감지 → A2 장면 합성 → A3 미래 외삽 → A4 나이 앵커 → A5 파노라마 → A6 영상화 → A7 릴 → A8 장례식 → A9 장지 → A10 캡션 업로드

## A1. 성별 감지

**기능** — 수집 앱이 성별을 안 받으므로, 이후 모든 이미지 프롬프트의 인물 명사(`Korean man/woman/boy/girl`)를 정하기 위해 프로필당 1회 레퍼런스 사진에서 추정. 서사 판단이 아닌 물리 묘사 재료.

- **INPUT**: 레퍼런스 사진 1장 (제출 사진 중 얼굴 앵커)
- **처리**: Gemini 캡션(사진을 한 문장 묘사) → 문장 속 성별 단어 카운트(`woman/she/girl…` vs `man/he/boy…`), 동수면 null
- **OUTPUT**: `manifest.gender = { value: 'male'|'female'|null, caption(근거), backend }` — 어드민에서 수동 수정 가능
- **모델**: `gemini-3.6-flash` (describeImage)

## A2. 장면 합성 (과거·현재) — `buildSynthesisPrompt`

**기능** — 참가자의 한국어 기록을 나이 격자마다 영어 장면 문장 2개(scene 1=반복 일상, scene 2=특정 사건)로 변환. 이 문장이 파노라마·릴 프롬프트의 핵심 재료. 감정·의미 해석 금지, 감각 재료(장소·빛·사물·행동)만.

- **INPUT**:
  - 점 배열 → `"event (함께한 사람: companion, 장소: place)"` 한 줄(한국어 원문 그대로)
  - 점의 실제 나이 + 영어 시기 라벨 고정표
  - influential/best/worst 선택 + 이유
  - 직업·모토·버킷리스트·묘비명·마지막 편지 (본인 소개 불릿)
- **OUTPUT**:
  ```json
  { "22": ["<scene 1>", "<scene 2>"], "34": ["<scene 1>", "<scene 2>"] }
  ```
- **품질 게이트**: 응답 수신 직후 JSON/키/개수 검증 + 두 장면 내용어 60%↑ 겹침 검사 → 실패 사유를 붙여 재요청(최대 3회)
- **폴백**: 글 없는 과거 나이는 LLM 없이 사람이 미리 쓴 `STAGES` 풀(10나이×5문장)에서 이름+생일 시드로 결정론 선택
- **모델**: `gemini-3.6-flash` (responseJson)

## A3. 미래 외삽 (부정 미래, 2장·2차 릴용) — 2단계

**기능** — 사용자가 점을 안 찍은 미래 나이를 "희망이 이뤄지지 않은 미래"로 외삽. ① 생애 연대기(사건 서사)를 먼저 쓰고 ② 그걸 나이별 장면으로 분해 — 나이 간 인과가 한 서사에서 나오게. 예측 배합은 인구통계 50% / 본인이 쓴 미래(어긋난 형태) 30% / 사주 10% / 예기치 못함 10%.

- **INPUT**: 과거~현재 기록 전체 + 본인이 쓴 미래 점 + 모토·버킷리스트·묘비명·편지(**first** 버전 — 체험 전 원본) + 이름/생년/현재나이/성별/직업
- **OUTPUT ①** (연대기): `AGE 40: <두세 문장>` × 미래 나이 수 (영어 평문)
- **OUTPUT ②** (장면): A2와 같은 JSON, 나이당 2장면. `sceneSource: 'extrapolated'`
- **고정**: 90세 마지막 한 장은 LLM이 아닌 상수 `FINAL_SCENE`(병상 임종)
- **모델**: `gemini-3.6-flash`
- 연대기는 런타임에서도 재사용된다(B3 미래 릴 큐레이션, B4 유령의 "이면" 배경)

## A4. 나이 앵커 (aged portrait) — `composeAgedPortraitPrompt`

**기능** — 4:1 파노라마는 얼굴이 작아 정체성+나이 변환을 동시에 못 살린다. 그래서 얼굴 앵커 사진에서 "그 나이의 같은 사람" 3:4 포트레이트를 먼저 크게 뽑아 캐시(`_aged/<age>.png`)하고, 파노라마·릴은 이걸 레퍼런스로 배치만 한다.

- **INPUT**: 얼굴 앵커 사진(우선순위: 어드민 `00-admin-face.*` > 최근 제출 사진), 목표 나이, isPast, 성별
- **OUTPUT**: 나이별 포트레이트 PNG 캐시. 아동 나이는 IMAGE_SAFETY 거부 시 앵커 없이 진행
- **모델**: `gemini-3-pro-image` (3:4)

## A5. 파노라마 30장 — `composeEquirectGazePrompt`

**기능** — 플랜(나이 격자 15개 × 나이당 2장 = **30장**)의 각 장면을 1인칭 360° equirectangular 4:1 파노라마로 생성. 실린더 투사용 원본. 마지막 90세의 2번째 장은 합성 결과를 덮어쓰고 고정 임종 장면(`FINAL_SCENE`)이 들어간다.

> ⚠️ 코드 주석 곳곳(`life-graph-plan.js` 상단, `profile-worker.js`, admin 등)에 "16개 나이 × 2장 = 32장"이라 적혀 있으나 **낡은 표현**이다. 현재 `AGE_TO_STAGE` 키는 15개(3·9·15·22·28·34·40·47·53·59·65·71·78·84·90)라 30장이 맞다(`buildLifeGraphPlan` 내부 주석도 "30장"으로 되어 있다).

- **INPUT**: 장면 문장(A2/A3) + 나이/연도/isPast + 성별 명사 + 얼굴 레퍼런스(아래 규칙) + descriptors
- **얼굴 레퍼런스 선택** (face-anchor):
  1. 그 시기 실제 제출 사진 있음 → **outpainting 접두어**(사진이 중심, 프레임 밖만 확장; 같은 나이 2번째 장면은 판박이 방지 접미어)
  2. aged 포트레이트 있음(기본) → **얼굴 유지 접두어**(재노화 금지)
  3. 폴백 → 현재 얼굴 + 나이 변환 단일패스 접두어
  4. 아동 세이프티 거부 → 레퍼런스 없이 텍스트만
- **OUTPUT**: `library/<pid>/<id>.png` (4096×1024, imageSize 4K) + manifest.images 항목(프롬프트·referenceKind 기록) + Firebase `generatedPanoramaImages` 업로드
- **모델**: `gemini-3.1-flash-image` (pro는 4:1 거부)

## A6. 영상화 (Wan2.2 I2V)

**기능** — 파노라마를 무한 루프 시네마그래프 영상으로. 사람은 제자리 정지(숨쉬기 수준), 움직임은 빛·공기·머리카락·옷자락만 — 4:1이 Wan 학습 분포 밖이라 사지를 움직이면 해부학이 붕괴하기 때문. 마지막 프레임=첫 프레임(심리스 루프).

- **INPUT**: 파노라마 PNG + `regen.promptPrefix`(시네마그래프 지시) + `WAN_NEGATIVE`
- **OUTPUT**: 장면별 mp4 (1920×480, 81프레임, 16fps) + 핑퐁 클립 캐시
- **실행**: ComfyUI (`workflows.js`의 Wan2.2 I2V 그래프)

## A7. 릴 사진 12장 × 2벌 — `composeReelPhotoPrompt` / `composeBirthPhotoPrompt`

**기능** — 주마등 회전 국면용 세로 3:4 사진 필름스트립. `past`(3세~현재, 1차가 역순 재생) / `future`(현재+1~90세, A3 외삽 장면 사용, 얼굴은 그 나이로 늙힘).

**나이 배분** — 두 벌이 **각각 독립적으로 12등분**된다: `round(start + (end-start)×i/11)`로 양 끝 포함 12점. 그래서 참가자 나이에 따라 "1장당 몇 년"이 크게 갈린다.

| 참가자 | 과거 릴 | 미래 릴 |
|---|---|---|
| 27세 | 3~27세 (약 2.2년 간격) | 28~90세 (약 5.6년 간격) |
| 70세 | 3~70세 (약 6.1년 간격) | 71~90세 (약 1.7년 간격) |

- 과거는 아주 어린 참가자면 반올림으로 **나이가 중복**될 수 있다(장면은 idx 시드로 다르게 뽑고, 같은 단계 풀에서 이미 쓴 장면을 피한다).
- 미래는 `Set`으로 중복을 제거하므로 남은 해가 짧으면 **12장 미만**이 된다(85세 → 5장, 90세 초과 → 미래 릴 없음).
- **과거 릴은 실제로 13장** — 12등분 앞에 탄생 사진(age 0)이 `unshift`로 붙는다. 서버가 재생목록을 역순으로 흘리므로 이 장이 주마등의 **마지막 이미지**가 된다(분만실에서 나를 안아든 엄마 — 주인공이 엄마라 얼굴 레퍼런스를 쓰지 않는 전용 프롬프트).

**얼굴 앵커** — 파노라마와 달리 **A4의 aged 포트레이트를 쓰지 않는다**(단일 패스). 3:4 근접 프레임은 pro가 "정체성 보존 + 나이 변환"을 한 번에 해내는 조건이기 때문. 레퍼런스는 3지선다: 그 시기 실제 사진(`stage`) → **현재 얼굴 사진 + 나이 변환 접두어**(`anchor`) → 없음(`none`).

- **INPUT**: 나이 사다리 + 장면(past=합성 장면 또는 STAGES 풀 / future=A3 외삽) + 연도 시대 고증 문구 + 얼굴 레퍼런스
- **OUTPUT**: `_reel/`, `_reel-future/` PNG + manifest.reelPhotos/reelPhotosFuture + Firebase `generatedReelImage` 업로드
- **모델**: `gemini-3-pro-image`
- 릴 나이(예: 23세)가 15구간 격자와 안 맞으면 `nearestStageAge()`로 가장 가까운 격자 나이의 합성 장면을 시드로 고른다

## A8. 장례식 — 2벌 (`present` 지금의 죽음 / `future` 90세의 죽음)

**기능** — 식장 한가운데 선 고인 1인칭 4:1 파노라마: 정면 중앙=제단·영정, 뒤쪽=조문객. 이미지 생성 → 어드민 승인 → Wan 영상화의 승인 게이트 구조. 5개의 하위 생성으로 조립:

| 하위 단계 | 기능 | 모델 |
|---|---|---|
| a. 영정 포트레이트 | 제출 사진(미래판은 _aged/90 얼굴) → 정장·정면 영정 3:4, `portrait[-future].png` 캐시 | pro-image |
| b. 조문객 캐스트 합성 | 생애 기록+장례 소망 → 실제 있었을 법한 조문객 4~6명 JSON `{who, appearance, imageAction, videoAction}`. 상주는 1번 필수, 편지 수신인 우선 | 3.6-flash |
| c. 장례 장소 합성 | 장례 방식·안식처 → 표준 식장인지/다른 공간(수목장 숲·바닷가·성당…)인지 판정 `{indoorHall, setting, altar}` | 3.6-flash |
| d. 파노라마 | 레퍼런스 2장(영정 포트레이트=액자 속 사진, 실측 360 식장 사진=구도만) 역할 라벨링 + 캐스트·상주·장소·나이 일관성 블록 조립 | flash-image |
| e. 모션 영상 | 시네마그래프 + 캐스트별 videoAction, 절(jeol)은 프롬프트·네거티브 양쪽에서 금지 | Wan2.2 |

- **INPUT**: 과거~현재 본인 텍스트(미래판은 +future 점, branched판은 +분기 연대기), funeral 소망 전체, 고인 나이(present=현재/future=90)
- **OUTPUT**: `funeral/funeral[-future]-r<rev>.png/.mp4`, manifest.funeral/funeralFuture (rev·승인·히스토리), Firebase 저장은 어드민 버튼

## A9. 장지 (grave) — `synthesizeGraveSetting` → `buildGravePrompt`

**기능** — 장례식 다음: 실제 묻힌 곳의 사람 없는 파노라마. 표지(묘비/수목장 표석/납골당…)를 정중앙에 두되 **명판은 완전 공백으로 생성**하고 묘비명 글자는 후처리(inscribeMarker)가 실제 폰트로 얹는다. variant `present`/`branched`(분기판은 1차와 다른 장소 강제).

- **INPUT**: burialSite·funeralMethod (branched는 +분기 연대기, 1차 장지 setting을 회피 대상으로)
- **OUTPUT**: 배경 판정 JSON `{setting, marker}` → `grave/grave[-branched]-r<rev>.png/.mp4` (레퍼런스 없이 텍스트만 생성)
- **모델**: 판정 `3.6-flash` / 이미지 `flash-image` / 영상 Wan2.2

## A10. futureLifeJourneyGraph 캡션 — `buildCaptionPrompt`

**기능** — 미래/분기 릴 12장마다 한국어 title(12자)·설명(30자)을 뽑아 사용자별 1문서의 negative(2차)/positive(3차) 필드에 업로드. 판정 어휘 금지, 장면 속 사실만.

**소비처** — 전시 런타임은 이 문서를 읽지 않는다. **컴포저**(크래프터 업데이트 버전 앱)가 생성된 미래를 참여자의 인생그래프에 이어 그릴 때 쓰는 노출용 정본이다: 항목의 `age`/`year`가 그래프 가로축, `title`(12자)이 점 라벨, `description`(30자)이 카드 한 줄, `imageURL`이 썸네일, `negative`/`positive`가 **두 갈래 미래 선**. 12자·30자 제약과 판정 어휘 금지가 여기서 나온다 — 두 갈래가 한 화면에 나란히 놓이므로 캡션이 우열을 판정하면 §미래 방향성 대비가 깨진다. 스키마를 바꾸면 컴포저 쪽이 깨지므로 함께 확인할 것.

- **INPUT**: 릴 12장의 `{id, age, year, scene(영어)}` 목록 + 이름
- **OUTPUT**: `[{id, title, description}]` JSON → Firestore `futureLifeJourneyGraph` (이미지 바이트는 안 올림 — `generatedReelImage`의 Storage URL 참조, merge라 다른 갈래는 유지)
- **모델**: `gemini-3.6-flash`
- **트리거**: 릴 생성 직후 자동 훅(best-effort) + 어드민 "인생그래프 요약 업로드" 버튼(`POST /api/future-journey/upload`)

# B. 런타임 — 1차 체험 (server/index.mjs)

## 국면 순서 (실제 흐름)

```
idle
 → spinup      실타래 배속 감김 (1차 개막만 2배 길이 — 돔 6왕복 안무와 세트)
 → funeral     현재 장례식(present) 영상 + 내레이션 B1
               → 클라이언트가 TV 꺼지듯 암전 → POST /api/funeral-done
 → grave       장지(묘비석 파노라마) 영상 → 암전 → POST /api/grave-done
 → reel        과거 릴 필름스트립 12장(역순) + 삶 회고 내레이션 B2
               → 스트립 1사이클 완료 시 reel-done (무응답 대비 deadman 폴백 有)
 → ghost 1장   RECAP_TAIL 개막 질문 → 과거 장면 3개 → 감사 → 후회 → 마지막 질문
 → [2장 전환]  ⓪ 전환 선언 발화 (유령 idle에서)
               ① playFutureSpinup — 실타래 10배속 감아올림 → 어둠
               ② playFutureFuneral — 90세 미래 장례식 1회 재생 → 암전   ※ 장지 없음
               ③ playFutureReel — 미래 릴 필름스트립 + 미래 큐레이션 B3
               ④ FUTURE_ASK 고정 질문 (시스템이 대신 말함)
 → ghost 2장   미래 장면 3개 + 사색적 질문 → 남은 생 자각 질문 → 종결 멘트 + 주마등 질문
 → finale      태풍소리 + 실 감김 역재생 → 암전
```

장례식은 총 2회(도입부 present + 2장 전환 future), 장지는 도입부 1회. 도입부가 `present`(지금 죽었다면)인 이유는 뒤따르는 주마등이 탄생~현재라 시간대가 맞기 때문 — `montage.json demo.funeralVariant: "future"`로 90세판 개막도 가능.
장례식·장지 영상이 아직 없으면(승인·영상화 전) 그 국면을 건너뛴다 — 전시가 멈추지 않는 게 우선. 국면 전환마다 ESP32 돔 안무 시리얼 송신.

**2차 체험(experience='second')은 한 바퀴만 돈다** — 과거 장 없음:
```
spinup → branched funeral(분기 90세 장례식) → branched grave(분기 장지)
       → branched reel(1차 미래 릴에서 "지지직" 갈아끼우는 fork 연출 + 큐레이션 B3 'branched')
       → ghost 미래 장(유령 주도 큐레이션 3장면) → 종결("두 갈래")
```
분기 장례식·릴이 아직 생성 전이면 1차 판으로 폴백한다.

## B0. 유령 에이전트 세팅 (`montage.json` → `ghost.voice`)

유령은 두 가지 방식으로 목소리를 낸다 — **내레이션**(B1~B3: 미리 만든 한 단락을 영상 위에 읽음, 일방향)과 **대화**(B4: 관람객 발화에 응답, 양방향). 목소리·TTS 설정은 둘이 공유한다.

### 엔진 구성

기본은 **bridge** — 세 조각을 서버가 직접 엮는다. `engine: "convai"`로 바꾸면 ElevenLabs Conversational AI SDK 한 세션이 STT·두뇌·TTS·턴테이킹을 모두 처리하지만, 그 경우 두뇌와 도구가 ElevenLabs 대시보드 설정으로 넘어간다(`agentId`는 이 모드 전용 — 현재 미사용).

| 역할 | 담당 | 값 |
|---|---|---|
| 듣기(STT) | 브라우저 | `webspeech` (기본) |
| 두뇌 | 서버 Gemini | `gemini-3.6-flash`, thinkingBudget 0(저지연) |
| 말하기(TTS) | ElevenLabs (서버가 중계) | `eleven_flash_v2_5` |

API 키는 전부 서버에만 둔다(`secrets/elevenlabs-api-key.txt`, `secrets/openai-api-key.txt`).

### 목소리

```
voiceId        Ip8ZgfdNlluBt9FGzcAN
ttsModelId     eleven_flash_v2_5
language       ko
speed          0.9      ← 2026-08-10 "빠르다" 피드백으로 1.0에서 하향
stability      0.75     ← 코드 기본값(명시 안 하면 요청마다 톤 편차가 커 발화마다 다른 목소리로 들림)
sentenceBreak  0.8초    ← 문장 경계마다 <break> 삽입 (2026-08-10 0.6→0.8)
```

> 페르소나 문서의 인물 묘사("젊은 남성")는 **오디오에 영향이 없다** — 실제 목소리는 `voiceId`가 정한다.

### 듣기 타이밍 (`listen` / 코드 상수)

```
endSilenceMs    2500    말이 끊긴 뒤 2.5초 조용하면 발화 종료로 판정
maxUtteranceMs 45000    한 발화 최대 45초
noSpeechMs     35000    유령이 말을 마친 뒤 35초 무응답 → 침묵 되물음 1회
startDelayMs    2600    유령이 화면에 뜨고 2.6초 뒤 첫 마디
```

브라우저 기본 끝점 감지를 쓰지 않는다 — 회상하다 멈칫하면 잘리므로, `endSilenceMs` 동안 조용해질 때까지 기다렸다가 그때까지 쌓인 문장 전체를 넘긴다. 침묵 되물음은 **질문마다 한 번**(관람객이 실제로 말하면 카운터 리셋).

### STT 대체 경로 (구현돼 있으나 현재 비활성)

```
stt.engine  "webspeech"        ← 기본. "realtime"으로 바꾸면 OpenAI Realtime 전사
stt.model   gpt-4o-transcribe   eagerness low · inputGain 3 · noiseReduction near_field
```

Realtime은 `semantic_vad`(침묵 길이가 아니라 말의 내용으로 끝점 판정 — 뜸 들여도 안 자름)가 장점이나, 2026-08-06 실측에서 한국어는 Web Speech가 더 나아 기본을 되돌렸다. 서버가 10분짜리 ephemeral 토큰을 발급해 OpenAI 키는 브라우저에 노출되지 않으며, 키 없음·연결 실패 시 Web Speech로 자동 폴백한다.

### 흐름별 페르소나

```
past.systemPromptPath    src/main/config/ghost-persona-past.md   (firstMessage 없음 — 서버가 RECAP_TAIL로 오버라이드)
future.systemPromptPath  src/main/config/ghost-persona.md        (firstMessage 고정문 有)
flow: "past"             수동 오버라이드용 — 실제로는 admin이 지정한 체험 차수가 우선
```

### 침묵 원칙 (§1)

유령은 **`ghost` 국면에서만** 말한다. 1인칭 진입(IMMERSION)·몽타주 재생 등 다른 국면에서는 renderer가 `stop()`으로 목소리를 끈다. 실패는 조용히 삼킨다 — 키 없음·마이크 거부·비보안 컨텍스트·쿼터 초과면 **소리 없이 유령만** 뜨고, 서버 TTS가 죽으면 브라우저 내장 TTS로 한 번 더 폴백한다.

## 내레이션 공통 배선 (B1~B3)

세 내레이션은 만들어지는 재료만 다르고 **재생 방식이 같다**.

- **문장 단위 개별 합성** — 통짜로 합성하면 ElevenLabs가 낭독조로 톤을 틀어버려서(2026-08-06 실측), 대화 턴과 같은 짧은 입력으로 맞춘다. `narrationChunks()`가 `<break>` 태그를 경계로, 나머지는 문장 단위로 쪼갠다.
- **정적은 클라이언트가 스케줄** — 서버는 텍스트에 `<break 3s>` 같은 페이싱을 심지 않고, `narrationGapMs`를 payload로 내려 renderer가 문장 사이 정적을 만든다. 장례식 1.5초 / 릴 3초.
- **사전 예열** — `prepareGhostPastAssets()`가 페르소나 로드 직후 백그라운드로 문장 단위 TTS를 미리 합성해 캐시한다(클라이언트 GET이 캐시에 바로 맞도록). 고정문 `RECAP_TAIL`·`FUTURE_ASK`도 함께 예열해 유령의 첫 마디가 지연 없이 나온다.
- **저장** — 완성된 큐레이션 멘트는 Firestore `lifeCuration`에 variant별(past/future/branched)로 남는다(best-effort — 실패해도 재생은 계속).
- **실패 시** — 생성이 실패하면 고정 폴백 문장을 쓰거나(회고), 내레이션 없이 진행한다(미래 릴).

## B1. 장례식 내레이션 — `composeFuneralNarration`

**기능** — 도입부 장례식 영상 위 내레이션. 고정 머리 뒤에 이 사람의 삶에 실제로 등장한 인물을 짚는 멘트를 생성해 붙인다.

- **INPUT**: companion 기록(점 배열의 `companion` 필드) + 본인 글(구 스키마 참가자는 글 속 인물이 후보)
- **OUTPUT**: `고정 머리 <break time="3s" /> 조문객 멘트 1~2문장`
  - 고정 머리: `잘 보이니? 너를 그리워하는 사람들이 이곳에 모였어. <break time="2s" /> 여긴 너의 장례식이야.`
  - 생성 멘트: `지현이도 왔고, 고모도 왔네.` — 성을 뗀 이름으로 친근하게, 두세 명이면 충분
  - 재료에 인물이 전혀 없으면 모델이 `"NONE"`을 반환 → 고정 머리만 나감
- **재생**: 장면이 뜨고 **5초 정적** 뒤 첫 마디(`FUNERAL_NARRATION_DELAY_MS`), 문장 간격 1.5초. 내레이션이 끝날 때까지 장면을 붙든다(`playFuneralOnce holdUntil`)
- **적용 범위**: 1차 체험 전용 — 2차(`experience='second'`)에서는 내레이션 없이 분기 장례식만 재생
- **모델**: `gemini-3.6-flash`

## B2. 삶 회고 (과거 릴 내레이션) — `composeRecapFirstMessage`

**기능** — 과거 릴이 흐르는 동안 얹히는 큐레이션 멘트("너는 ○○하고, ○○했지 … 삶을 살았구나"). 사실 범위는 본인 글로 제한하되 **유령의 말투로 재가공**한다 — 그대로 낭독하면 입력을 읽어주는 느낌이 나므로 가공을 허용했고, 대신 삶 전체의 의미 규정·훈계는 금지.

- **INPUT**: 과거~현재 점 텍스트(`{나이}세 무렵: "원문"` 목록), 현재 나이
- **OUTPUT**: 반말 6~8문장 한 단락, 마지막 문장은 반드시 `"…삶을 살았구나."`로 끝남
  - 폴백(생성 실패·재료 없음): `넌 아직 ${나이}살이지만, 짧다면 짧고 길다면 긴 삶을 살았구나.`
- **재생**: 릴이 1분 남짓 흐르는 동안 문장 사이 **3초 간격**으로 이어짐. 릴 국면에서 흐르므로, 이어지는 유령 개막에는 회고 없이 `RECAP_TAIL` 질문만 남는다(2026-08-06 이동)
- **모델**: `gemini-3.6-flash`

## B3. 미래 릴 큐레이션 — `composeFutureRecapMessage`

**기능** — 미래 릴 위 내레이션("너의 삶이 이대로 지속된다면, 넌 ○○를 하고, ○○해"). 부정 사건을 응축해 나열하면 협박처럼 들려서(2026-08-10 실측 — 간병·사망·요양원이 연달아 나왔다), 배경은 담담한 일상으로 두고 어긋남의 흔적은 **딱 하나만** 짚는다. 그 하나도 아무 불행이 아니라 본인이 힘들었다고 남긴 기록의 주제와 개연성 있게 잇는다.

- **INPUT**: A3(부정)/C1(분기) 연대기 + worst 선택(+이유) + 그래프 x 저점 3개
- **OUTPUT**: 반말 5~7문장 한 단락. 판정·질문·훈계 없음, 문어체(`-ㄴ다`)와 예언조 금지
- **kind 두 벌**: `future`(1차 2장 전환 — 부정 미래) / `branched`(2차 체험 — 분기 미래). 프레이밍 문단과 가공 규칙이 갈린다
- **재생**: 릴 위에 문장 3초 간격. 질문은 붙이지 않는다 — 릴이 끝난 뒤 유령이 따로 묻는다(2장=`FUTURE_ASK` 고정문, 2차 체험=montage.json `firstMessage`)
- **모델**: `gemini-3.6-flash`

## B4. 유령 대화 턴 — bridge 엔진 (`/api/ghost/turn`)

**기능** — 대화의 두뇌. 관람객 발화(STT) 또는 상황 알림을 받아 유령의 대사(`say`)와 띄울 장면(`show`)을 JSON으로 결정한다.

### 프롬프트 조립 (턴마다 새로)

```
페르소나 문서(질문 목록 주입)
  + 장면 카탈로그 (+ 2차 체험은 "원래 갈래 비교" 정보)
  + 미래/분기 연대기 = "너만 아는 이면"
  + 출력 형식 규칙
  + 지금 단계 지시   ← 서버가 단계 상태로 계산해 매 턴 주입
  + 지금까지의 대화 (최근 24턴)
```

- **페르소나**: `ghost-persona-past.md`(1차) / `ghost-persona.md`(분기 미래)
- **질문 목록** (`reflective-questions.mjs`): 페르소나의 `{{PAST_QUESTIONS}}`·`{{FUTURE_QUESTIONS}}` 자리에 주입. 이미 던진 본질문에는 **"(이미 던졌다)"** 표시가 붙는다(서버가 응답의 `q` 필드로 추적). ⚠️ **자리표시자는 `ghost-persona-past.md`에만 있다** — 분기 미래 페르소나에는 질문 목록이 아예 실리지 않는다
- **장면 카탈로그**: `- id 6-2 · 34세 · 2022년 · <scene>` 형식. 1차는 과거+미래 두 절로 나뉘고 장별로 고를 수 있는 절이 제한된다 (조립 방식은 아래 별도 소절)
- **이면(연대기)**: 화면에 없는 각 시기의 사정. 한 턴에 **한 조각만** 흘리고, 관람객이 물으면 연대기의 사실로 답한다(판정·위로 금지, 없는 불행 지어내기 금지)
  - ⚠️ **1장부터 프롬프트에 들어가 있다.** 헤더가 `## 미래 각 시기의 이면 (연대기 — 너만 아는 배경, 2장에서만)`이고 본문이 "미래 장면을 보여주거나 그 시기 이야기를 나눌 때"로 제한하지만, **하드 필터가 아니라 지시로만 막는 소프트 게이트**다(장면 카탈로그는 절을 나누고 단계 지시가 한 번 더 못 박는 이중 방어인 반면, 연대기는 그런 이중 방어가 없다). 실질적으로는 1장 내내 단계 지시가 과거 장면 감상만 시켜서 새어 나갈 자리가 잘 생기지 않는다
  - 분기 미래 세션은 헤더가 `## 이 시간선 각 시기의 이면`이고 "2장에서만" 제한이 없다(그 세션은 처음부터 미래 장이므로)
- **대화 기록**: 최근 **24턴**. 실제 대화가 22턴 내외라 사실상 전체가 늘 프롬프트에 들어간다(3차 재료인 `ghostTranscriptAll`은 잘림 없이 전량 저장 — 24턴 제한과 무관)

### 장면 카탈로그 조립 (`momentsCatalog`)

저장되는 데이터가 아니라 **매 턴 새로 조립**된다(세션 발급 시 + 대화 턴마다). 배열 순회 + 파일 존재 확인이라 비용이 낮고, 대신 세션 중에 영상이 새로 준비되면 다음 턴에 바로 후보로 들어온다.

1. **현재 나이** — 프로필을 조회하지 않고 장면에서 역산한다(`year - age` = 출생연도)
2. **갈래 필터** — `branch` 플래그로 1차용(본편)과 분기용을 분리
3. **영상 필터** — `regenerator.cachedPath(id)`가 없으면 제외. **이미지만 있고 영상이 없는 장면은 후보에서 빠지므로, 카탈로그 장수는 본편 30장보다 적을 수 있다**
4. **과거/미래 판정** — `sceneSource`가 아니라 **나이 비교**(`age > currentAge`)
5. **url** — 핑퐁 변환본(`.pp.mp4`)이 있으면 그것, 없으면 원본 plain loop. 이 url은 프롬프트에 노출되지 않고 서버가 들고 있다가 유령이 id를 고르면 클라이언트에 내려준다
6. 나이순 정렬 → 텍스트 목록으로 렌더

**카탈로그에 담기는 장면의 출처**는 A2에 한정되지 않는다 — manifest의 항목 전체가 후보이므로 `user`(A2 합성) · `fallback`(STAGES 풀) · `extrapolated`(A3 외삽) · `final`(고정 임종)이 모두 섞인다. 유령에게는 넷이 구분되지 않는다(`sceneSource`는 프롬프트에 안 들어감). 실측 예: 본편 30장 = user 16 / extrapolated 13 / final 1.

**나이당 2장이 대화 구조를 만든다** — 본편은 나이당 2장(일상/사건)이라 "이 시기의 다른 모습도 보여줄까?" 선택지가 성립하고, 서버가 `age === lastAge && !seenIds.includes(id)`로 남은 후보를 계산해 없으면 그 선택지를 제안하지 않는다. 분기 장면은 나이당 1장이라 이 선택지가 구조적으로 사라진다.

### 질문 목록 규모와 소비

| | 결 | 본질문 | 꼬리 | 합 |
|---|---|---|---|---|
| 과거 P | 6 | 12 | 24 | **36** |
| 미래 F | 5 | 10 | 20 | **30** |

목록 전체가 매 턴 실리지만 실제 소비는 **6자리 안팎**이다.

- **1장(4자리)**: 첫 장면 후속 = 감사(P4-1 고정 슬롯) · 두 번째 장면 사색 질문 1 · 마지막 장면 사색 질문 1('후회' 결 제외) · 종결 = 후회(P5-1 고정 슬롯)
- **2장(2자리)**: 두 번째·마지막 장면에 각 1개 (**F 목록에서만** — 과거 질문 P는 회상 화법이라 금지)
- **분기 미래(0자리)**: 목록 자체가 미주입. 장면마다 질문 대신 "궁금한 거 있으면 물어봐"로 자리를 연다

여기에 **목록 밖 고정 질문 4개**가 더 있다: "왜 이때의 모습이 보고 싶었어?"(장별 첫 장면) · "끝내 하지 못한 말"(1장 마지막) · "남은 생애의 전부라면"(2장·분기 마지막) · 종결의 주마등 질문(대답을 기다리지 않음).

첫 장면에 사색적 질문을 안 쓰는 것은 **질문 다이어트**(2026-08-05) 때문이다. 꼬리 질문은 "본질문 답을 들은 다음 턴에 이어가라"고 되어 있으나 단계 지시가 박자를 촘촘히 정해 실제로 쓸 자리는 많지 않다.

### 턴 수 (추정)

고정된 것은 **장별 영상 3개씩**(`GHOST_CHAPTER_TARGETS = { past: 3, future: 3 }`)뿐이고 턴 수는 거기서 파생된다. 되묻기·관람객 질문·침묵이 없는 이상적 진행 기준으로 **1장 약 12턴 + 2장 약 10턴 = 22턴 내외**(관람객 발화 약 14회, 시스템 상황 알림 6회). 분기 미래는 한 장만 돌아 **약 10턴**.

체험별 영상 수: **1차 방문 = 과거 3 + 미래 3 = 6개**, **2차 방문(분기) = 3개**.

### 지금 단계 지시 (서버가 강제하는 진행)

**무엇인가** — 서버가 매 턴 계산해 프롬프트 맨 끝(`## 지금 단계 지시` 헤더 아래)에 붙이는 **한국어 지시문 한 덩이**다. 페르소나·카탈로그·연대기는 턴마다 거의 같지만 이 블록만 매번 바뀌며, "이번 응답에서 정확히 무엇을 하라"를 문장으로 못 박는다. 실제 텍스트는 이런 모양이다:

```
(지금 단계: 첫 장면 감상) 장면을 건넬 때 순서를 짚어라 — 첫마디를 "이게 첫 번째 순간이야" 같은
결로 시작한다. 장면을 천천히, 구체적으로 묘사하라 — 장소와 시간대, 이 사람이 하고 있는 일,
주변의 공기 같은 디테일을 서너 문장 이상 … 그리고 마지막에 "왜 이때의 모습이 보고 싶었어?"
하나만 물어라 — 다른 질문은 덧붙이지 않는다. show 금지. (예외: 사람이 명시적으로 다른 모습을
보여달라고 요청할 때만 …) 이미 보여준 장면 id: 3-1 — 다시 보여주지 않는다.
```

**왜 필요한가** — LLM은 매 턴 프롬프트를 새로 받으므로 "지금이 몇 번째 장면인지, 질문을 몇 번 던졌는지"를 스스로 셀 수 없다. 페르소나 문서에 "장면 3개를 보여줘라"라고만 써두면 두 번째 턴에 세 개를 다 보여주려 하거나 종결 대본을 미리 꺼낸다. 그래서 서버가 `ghostFlow` 상태(`chapter`·`videosShown`·`replies`·`seenIds`·`seenAges`·`lastAge`)를 추적해 **지금 허용된 행동 하나만** 내려보낸다.

**한 덩이에 담기는 것**: 이번 턴에 show를 넣을지 / 넣는다면 고를 수 있는 id 후보 / 질문을 던질지·어느 목록에서 / 어떤 문구로 끝낼지 / 이미 본 장면 목록 / 관람객이 명시적으로 다른 장면을 요청했을 때의 예외.

**규칙 요약**

- 장별 영상 **3개씩**(`GHOST_CHAPTER_TARGETS = { past: 3, future: 3 }`)
- **홀짝 리듬** — 홀수 번째 = 새 시점 첫 장면, 짝수 번째 = 같은 시기의 다른 장면. 홀수 뒤엔 "같은 시기 / 다른 시간선" 선택지(3가지 문구를 번갈아 써 기계적 반복 방지), 짝수 뒤엔 새 시점 질문. 같은 나이에 안 본 장면이 없으면 선택지 자체를 건너뛴다
- **박자 강제** — 1장: 감사 → 후회 → 마지막 질문("끝내 하지 못한 말") → 전환 선언 / 2장: 남은 생 자각 질문 → 종결 멘트 + 주마등 질문
- 박자 판정은 카운터가 아니라 **직전 유령 발화의 내용**으로 한다(STT가 발화를 쪼개도 순서를 건너뛸 수 없게): `후회` 포함 여부, `끝내 하지 못한 말` 구절, `주마등`+`담겨|닮아` 조합. 그래서 지시문이 그 구절을 발화에 반드시 넣도록 강제한다 — 지시와 검사가 짝을 이룬다
- **침묵 되물음**은 단계 지시를 대체하되 상태(replies 등)는 건드리지 않아, 되물음 뒤 실제 대답이 오면 원래 흐름이 이어진다. 트리거는 **35초 무응답**(`noSpeechMs: 35000`)이며 질문마다 한 번
  - ⚠️ 되물음 지시문 본문에는 `"방금 네 질문에 12초 넘게 대답이 없다"`로 **옛 값이 남아 있다** — 클라이언트 대기(35초)·이벤트 텍스트(`(침묵: 35초 넘게 대답이 없다)`)와 어긋난다. 발화에 시간을 언급하라는 지시가 없어 겉으로 드러나진 않지만, 고칠 때 세 곳을 함께 맞출 것
- **2차 체험**은 `branch: true` 가지 — 관람객이 고르길 기다리지 않고 유령이 "원래 갈래와 가장 달라진 장면"부터 큐레이션, 장면마다 질문 대신 "궁금한 거 있으면 물어봐"로 자리 열기

### 출력과 검증

- **OUTPUT**: `{"say":"...", "show":{"id":"6-2","exact":true}, "q":"P2-1"}`
  - `say` = 지금 음성으로 말할 두~다섯 문장 / `show` = 새로 띄울 장면(없으면 생략) / `q` = 방금 쓴 본질문 id(서버가 추적해 "이미 던졌다" 표시)
- **show 검증**: 카탈로그에 없으면 나이 근접 장면으로 폴백(`exact=false`). 금지된 show(이미 보여준 장면·상황 알림 턴의 에코)나 **약속만 하고 show 누락**("기다려봐" 발화인데 show 없음)이면 교정 지시를 붙여 1회 재생성하고, 재시도도 어기면 show만 버린다
- **부수 출력**: 전 대화가 Firestore `ghostTranscripts`에 **세션 키별로** 업서트 → **3차 합성(C1)의 1순위 재료**. 세션 키를 나누므로 재방문해도 이전 대화가 덮이지 않는다
- **모델**: `gemini-3.6-flash` (thinkingBudget 0 — 대화는 저지연이 생명)

# C. 3차 합성 & 2차 체험 (processBranchedFuture → 재방문)

## C1. 분기 미래 합성 (긍정 미래) — 2단계

**기능** — 1차의 유령 대화 기록이 생긴 뒤에만 실행. 대화에서 드러난 소망·후회로 "원하는 대로 잘 풀린" 분기 미래를 외삽. 핵심 규칙: 소망은 체크리스트가 아니라 **2~3개만 선별**, 가치를 번역해 간접 실현(직역 금지 — "세계여행"이면 공항 아닌 외국 시장의 아침 장보기), 현실적 비용·잔여 유지.

- **INPUT**: **유령 대화 전문(1순위)** + 프로필 전체(과거 점, 미래 점, 모토·버킷리스트 **latest** — 체험 후 재작성분 우선, 묘비명·편지)
- **OUTPUT ①** 분기 연대기 (`AGE n: ...`) ② 나이당 **1장면** JSON. `sceneSource: 'branched'`, plan id `alt-<나이>-<n>`, branch:true
- **모델**: `gemini-3.6-flash`

## C2. branched 산출물

C1 장면으로 A5~A9와 같은 기계를 재사용: 분기 파노라마(branch 장면), **분기 릴**(`_reel-branched/`), **분기 장례식**(funeralBranched — 분기 연대기가 조문객 1순위 근거), **분기 장지**(graveBranched — 1차와 다른 장소 강제), 캡션 업로드(positive).

## C3. 2차 체험 세션 (재방문)

**기능** — admin이 experience='second' 지정 시 입장 의례(spinup → 분기 장례식 → 분기 장지 → 분기 릴, B 절 참조)를 거쳐 유령 세션이 곧장 미래 장으로 시작. 유령이 **큐레이션 주도**: 카탈로그의 "원래 갈래 비교" 정보로 가장 달라진 장면부터 순서대로 3개 show(비교 기준은 입 밖에 안 냄, 대조 화법 금지). 장면마다 질문 대신 "궁금한 거 있으면 물어봐"로 자리 열기, 비가족 인물은 "네가 직접 물어봐"로 회피. 종결은 "두 갈래" 모티프의 전용 멘트.

- **INPUT**: ghost-persona.md + 분기 장면 카탈로그(+원래 갈래 비교) + 분기 연대기(이면) + montage.json firstMessage. **질문 목록은 실리지 않는다**(자리표시자가 1차 페르소나에만 있음)
- **OUTPUT**: B4와 동일한 턴 구조. 대화는 새 세션 키로 ghostTranscripts에 누적
- **장면 3개** — 나이당 1장면이라 "같은 시기의 다른 모습" 선택지가 없고, 유령이 매번 새 시기를 순차 큐레이션한다
- **질문을 아예 안 하는 것은 아니다** — 장면 감상 구간에서만 사색적 질문을 접고, 체험을 닫는 두 질문은 그대로 던진다: 마지막 장면 뒤 "남은 생 자각" 질문(1차 2장과 공유), 종결의 주마등 질문("오늘 본 두 갈래 중 어느 쪽을 닮아 있을까")
- **턴 수** 약 10턴(한 장만 돌기 때문)
